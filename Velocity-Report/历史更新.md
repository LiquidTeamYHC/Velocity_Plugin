# VelocityReport更新日志

## VelocityReport v2.3.0 (2026-10-10)

### 新增

- **离线举报** — 玩家下线后 24 小时内仍可被举报。插件在登录 / 切服 / 退出时把「最后在线时间 + 子服」写入新表 `player_last_seen`；在线玩家不受限制，Tab 补全也会列出窗口内的离线玩家。窗口由 `offline-report-window-hours` 控制（默认 `24`，`0` 关闭）
- **`/reportadmin`（别名 `/ra`、`/reportadm`）** — 管理总入口，不带参数显示帮助：`reload`、`list`、`view`、`close`、`resolve|reopen`、`history`、`staff add|remove|list`
- **`/reportstaff`** — 游戏内增删管理员名单，写入 `staff-users.yml`，与 config.yml 的 `staff-users` 合并生效（config.yml 不会被插件改写）

### 变更

- **服务器别名移到 config.yml**：`server-aliases: { lobby: "&e登录服" }`；旧的列表写法 + lang 里的 `server-alias-*` 仍兼容，但以后加别名不用再改语言文件
- **旧重载命令 `/reportreload` 已移除**，改用 `/reportadmin reload`（`/ra reload`）
- **权限**：重载单开节点 `velocityreport.reload`，与 `velocityreport.staff` 互不通用；管理命令现在也认 `staff-users` 名单内的玩家（以前名单只管通知，没装权限插件的服务器等于用不了命令）
- 默认配置的 `staff-users` 示例名单清空为 `[]`；`/report` 不带原因时会先校验目标能否举报；语言文件会自动补齐新增的消息键

### 注意事项

- `player_last_seen` 是自动创建的新表，但**升级瞬间是空的**：玩家要重新上/下线一次才会被记录（在线玩家不受影响）
- 原来靠 `velocityreport.staff` 重载的人，升级后需要补 `velocityreport.reload`

## VelocityReport v2.1.0 (2026-07-05)

### 1. MySQL 连接优化 — HikariCP 连接池

**问题：** 旧版使用单条 JDBC 长连接，MySQL `wait_timeout`（默认 8 小时）超时后连接断裂，导致 `Broken pipe` 报错，插件无法继续使用。

**解决：** 引入 HikariCP 连接池，自动管理连接生命周期。

| 配置项 | 值 | 说明 |
|---|---|---|
| 最大连接数 | 10 | 足够 Velocity 代理使用 |
| 最小空闲 | 3 | 保持基本连接池 |
| 连接超时 | 5 秒 | 获取连接等待时间 |
| 空闲超时 | 10 分钟 | 回收空闲连接 |
| 最大寿命 | 30 分钟 | 远低于 MySQL 8h 的 wait_timeout |
| 保活检测 | 5 分钟 | 定期探测空闲连接 |

### 2. 语言文件重构

语言文件统一放在 `lang/` 文件夹下，首次启动自动生成到插件目录。

```
plugins/velocity-report/
├── config.yml
└── lang/
    ├── zh_CN.yml    ← 简体中文
    └── en_US.yml    ← English
```

**配置语言：** 修改 `config.yml` 中的 `language` 项：
```yaml
language: zh_CN   # 简体中文
language: en_US   # English
```

### 3. 举报原因 & 服务器别名多语言化

举报原因的显示名称和描述、服务器别名现在跟随语言设置自动切换。

**中文效果：**
```
举报原因：外挂作弊、违规言论、熊孩子
服务器：登录服、生存服、小游戏
```

**英文效果：**
```
Reasons: Hacking, Chat Violation, Griefing
Servers: Lobby, Survival, Minigame
```

### 4. 体积优化

SQLite JDBC 原生库从 23 个平台精简到常见的 5 个，JAR 体积从 **17MB → ~5MB**。

保留的平台：
- Linux x86_64（主流服务器）
- Linux aarch64（ARM 云服务器）
- Windows x86_64
- Mac x86_64 / aarch64（开发测试）

## 配置文件指南

### 举报原因配置

`config.yml` 只定义 id 和 icon，显示文本在语言文件中：
```yaml
report-reasons:
  - id: "hacking"
    icon: "⛏"
  - id: "other"
    icon: "📋"
```

语言文件 (`lang/zh_CN.yml`)：
```yaml
reason-hacking: "&c外挂作弊"
reason-hacking-desc: "KillAura, ESP, AutoClicker 等作弊行为"
```

### 服务器别名配置

`config.yml` 里直接写「子服名: 显示文本」，显示文本支持 `&` 颜色代码：
```yaml
server-aliases:
  lobby: "&e登录服"
  survival: "&a生存服"
  minigame: "&6小游戏"
```

子服名必须与 Velocity 里的服务器名完全一致（区分大小写）；没列进来的子服显示原始名字。
语言文件里不再配置别名（2.3.0 起）。

> 2.3.0 之前的老写法（`server-aliases` 写成列表 + `lang/*.yml` 里的 `server-alias-<名字>`）仍然可用，但已不推荐。

## 升级注意事项

- 旧版 `lang_zh.yml` / `lang_en.yml` 不再使用，如有自定义内容请迁移到 `lang/zh_CN.yml` / `lang/en_US.yml`

- SQLite 用户不受影响

## v2.0.0 (2026-07-04)

### ✨ 新增功能

#### 举报原因选择菜单
- `/report <玩家>` — 现在不带原因输入时会显示可点击的聊天菜单
- 支持多种预设原因：外挂作弊、违规言论、熊孩子、管理员神权等
- 点击即可提交，无需手动打字
- 原因模板可在 `config.yml` 中自由增删改

#### 举报管理菜单 (`/reportcd`)
- `/reportcd` — 打开全部举报记录列表（支持分页）
- `/reportcd list <页码> [玩家名]` — 按页查看，可筛选特定玩家
- `/reportcd view <编号>` — 查看举报详情
- `/reportcd resolve <编号>` — 标记为已处理
- `/reportcd reopen <编号>` — 重新标记为未处理
- 列表和详情页都支持点击交互，无需记忆命令

#### 举报人通知
- 管理员标记举报为已处理后，自动通知举报人
- 通知内容：`你的举报 #编号 已标记为已处理。`

### 🔄 其他
- 点击聊天菜单支持翻页导航
- 发布版本号更新

## v1.1.0 (2026-07-04)

### ✨ 新增功能

#### MySQL 数据库支持
- 新增 `MySQLReportStorage` 实现
- 配置 `database.type: mysql` 即可切换
- 自动建表，无缝迁移

#### 中文语言支持
- 全部消息默认中文
- 支持 `&` 传统颜色代码（`&c` 红色、`&e` 黄色等）
- 所有消息可通过 `config.yml` 自定义

#### 服务器名称映射
- 配置 `server-aliases` 可将原始子服名显示为自定义文本
- 例如：`lobby → &e登录服`
- 支持 `&` 颜色代码

#### Tab 补全
- `/report <玩家>` 按 Tab 自动补全在线玩家名
- 支持按前缀筛选

#### 热重载
- `/reportreload` — 重新加载 `config.yml`
- 改冷却、消息等无需重启代理

#### 管理员名单
- `staff-users` 配置项，无需 LuckPerms 即可指定管理员
- 不区分大小写

### 🐛 修复
- 修复通知消息前缀重复显示的问题（`[举报][举报]` → `[举报]`）
- 修复 SQLite 驱动在打包后未自动加载的问题
- 修复无权限插件时自定义权限一律返回 false 的问题
- 移除控制台举报通知重复输出

### 🔄 其他
- 新增 `velocity-report.json` 插件清单
- 重构存储层为接口设计（`ReportStorage` + `SQLiteReportStorage` + `MySQLReportStorage`）
- 优化初始化流程
